# Contributing to Atrinik

Thank you for helping Atrinik. Search existing issues and the
[Atrinik work project](https://github.com/orgs/atrinik/projects) before opening
new work so related efforts can share one discussion.

Use the repository that owns the affected component. Bug reports should include
the smallest reproducible scenario, expected behavior, actual behavior, and
relevant logs. Feature requests should describe the user-visible outcome and
acceptance criteria before proposing an implementation.

Pull-request titles and commits use Conventional Commits style, for example
`fix(server): reject malformed login packets`. Keep changes focused, link the
issue they resolve, and include automated and manual verification. Repository
instructions and contribution guides override this organization default.

By participating, you agree to follow the
[Atrinik code of conduct](https://github.com/atrinik/.github/blob/main/CODE_OF_CONDUCT.md).
